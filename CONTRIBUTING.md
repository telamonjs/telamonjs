# Contributing to TelamonJS

TelamonJS is a pnpm monorepo: the packages live in `packages/*`, the docs site
in `apps/docs` and a generated example app in `apps/example`. AI agents should
also read [AGENTS.md](./AGENTS.md), which lists the traps that cost the most time.

## Setup and the gates, in order

You need Node ≥ 22. pnpm is pinned in `package.json` (`packageManager`), so let
corepack provide it, or call a global `pnpm` directly: it switches to the
pinned version on its own.

```bash
pnpm install
pnpm build        # ALWAYS first: workspace packages resolve types from dist/
pnpm lint
pnpm type-check
pnpm test
```

If you run `type-check` or `test` before `build`, they fail with
`Cannot find module '@telamonjs/logger'`. That means the build is missing, not
that an import is broken. CI runs the commands in exactly this order.

**Redis for `packages/queue`.** The queue suites need Redis on
`127.0.0.1:6379`. Without it, the Redis-dependent suites skip; CI runs them all.

```bash
docker run -d -p 6379:6379 redis:7-alpine
```

## Docs workflow

The site lives in `apps/docs` (MDX under `apps/docs/content/docs`). It is not
part of the aggregate scripts, and its live previews import the packages'
`dist/`, so build the packages first.

```bash
pnpm docs:generate   # regenerate docs/exports.md, llms.txt, llms-full.txt and the README blocks
pnpm docs:check      # links, imports and content rules (runs in CI)
pnpm docs:build      # static build of the site
pnpm docs:dev        # local preview on http://localhost:3001
```

Generated files are committed. CI fails when they are stale, so run
`pnpm docs:generate` after changing exports, entry points or peers. Do not hand-edit
the blocks between `<!-- generated:… -->` markers in the package READMEs.

## Example app

`apps/example` is a complete admin app (sign-in, a users CRUD module,
dashboard, pt-BR/en/es) generated by the CLI and wired to the workspace
packages. Do not edit it by hand: change `packages/cli/templates` and regenerate.

```bash
pnpm --filter @telamonjs/cli build && pnpm example:generate
pnpm example:dev     # http://localhost:3001 (same port as docs:dev, so run one at a time)
```

It needs a PostgreSQL `DATABASE_URL` and a `NEXTAUTH_SECRET` in
`apps/example/.env` (copy `apps/example/.env.example`), then
`pnpm --filter @telamonjs/example db:push` and `db:seed`.

Working on the CRUD generator? The file-by-file walkthrough of its output is
in [`packages/cli/src/commands/generate/EXAMPLE.md`](./packages/cli/src/commands/generate/EXAMPLE.md).

## The public API is pinned

`packages/ui/src/__snapshots__/index.test.ts.snap` lists every name the
`@telamonjs/ui` root barrel exports, and `src/index.test.ts` fails when that list
changes. A snapshot diff is a deliberate public-API change, never "a test to
fix": update it on purpose (`pnpm --filter @telamonjs/ui test index -u`), say so
in the commit, and add a changeset with the right bump.

## Changesets and releases

Every change that should reach npm ships with a changeset:

```bash
pnpm changeset            # pick the packages, the bump and write the summary
```

Maintainers run `pnpm version-packages` (applies the changesets: versions,
CHANGELOGs, lockfile) and commit it. When CI passes on `main`, the Release workflow
(`.github/workflows/release.yml`) publishes the new versions to npm through trusted
publishing and pushes the release tags. No npm token is involved.

## Commits and code

- [Conventional Commits](https://www.conventionalcommits.org/): `type(scope): description`,
  for example `fix(ui): keep the dialog open on a failed mutation`.
- TypeScript strict with no `any` (use `unknown`), named exports only.
- Tests are co-located (`Component.test.tsx` next to `Component.tsx`). New
  components ship with tests, including `vitest-axe` assertions against real primitives.
- Library UI text goes through `packages/ui/src/i18n/messages`. `pnpm lint` fails on a stray pt-BR literal.
