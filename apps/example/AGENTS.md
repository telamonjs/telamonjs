# AGENTS.md — This App

This app was generated by the `@telamonjs/cli` CLI (bins
`create-telamonjs-app` and `telamonjs`). It runs Next.js 15 (App Router) + React 19 + TypeScript 5
(strict), Prisma, Zustand, React Query, Zod, NextAuth v5.

You are an agent working **inside a generated app**, not inside the
framework's own monorepo. Two rules before anything else:

1. **Evidence rule.** Never use a component, prop, or field type from
   memory or from an older example. Before using any symbol from a
   `@telamonjs/*` package, confirm it exists in the installed version: grep
   its shipped types, `node_modules/@telamonjs/*/dist/**/*.d.ts` (each
   package's `README.md` sits next to them). If you can't find it there, it
   does not exist — ask before inventing it.
2. **This app has its own module of reference.** `src/app/admin/usuarios/`
   is a complete, working CRUD module built with every pattern below. When
   in doubt, read it before asking or guessing.

## Shell composition (canonical, do not build a custom sidebar)

The whole app shell — sidebar, header, command palette, breadcrumb — comes
from one component: `AdminShell`. Do not hand-roll a sidebar, a
`LayoutProvider`, or a flat menu array.

```
src/app/admin/layout.tsx
  │   (Server Component: calls auth(), redirects without session.user)
  └── LayoutProviders ('use client', passes the session to AdminShell)
        └── AdminShell            ('use client', from the library)
              ├── ModernSidebar   (menu + collapse + mobile drawer)
              ├── CommandPalette  (Cmd+K, built from menuConfig)
              ├── ResponsiveBreadcrumb (auto-detects route)
              └── {children}
```

`src/config/menu.ts` — the typed menu:

```typescript
import type { MenuItem } from '@telamonjs/ui'

export const menuConfig: MenuItem[] = [
  {
    id: 'dashboard',
    type: 'single',
    title: 'Dashboard',
    href: '/admin',
    icon: 'LayoutDashboard', // STRING — resolved internally via getIcon()
  },
  {
    id: 'admin-group',
    type: 'group',
    title: 'Administration',
    icon: 'Settings',
    children: [
      { id: 'users', type: 'single', title: 'Users', href: '/admin/users', icon: 'Users' },
    ],
  },
]
```

**Rule: icons in the menu are always a string** (a lucide-react key), never
an imported Lucide component. The app registers its own icon set once at
boot via `setIconResolver((name) => iconRegistry[name])` — the registry
belongs to the app, not to the library. A name missing from the app's
registry silently renders as a generic circle instead of throwing, so a
typo is a silent bug, not a crash — double-check the string against your
registry.

`src/components/providers/LayoutProviders.tsx`:

```tsx
'use client'
import { useRouter } from 'next/navigation'
import type { Session } from 'next-auth'
import { AdminShell, Toaster } from '@telamonjs/ui'
import { menuConfig } from '@/config/menu'

  const router = useRouter()

    <>
      <AdminShell
        menuConfig={menuConfig}

        systemName="YourApp"

        compactLogoUrl="/icon-compact.png"
        onSignOut={() => router.push('/sign-out')}
      >
        {children}
      </AdminShell>
      <Toaster />
    </>
  )
}
```

## Dashboards with tabs

A page with several sub-views is one page with tabs — never several
standalone pages. `src/app/admin/page.tsx` demonstrates the pattern:

```tsx
'use client'
import { ShellPage, AdminHeader, AdminTabs, useTabUrlSync, type TabItem } from '@telamonjs/ui'

const TAB_VALUES = ['overview', 'details'] as const

const tabs: TabItem[] = [
  { value: 'overview', label: 'Overview', content: <OverviewTab /> },
  { value: 'details', label: 'Details', content: <DetailsTab /> },
]

export default function DashboardPage() {
  const { activeTab, setTab } = useTabUrlSync({ tabs: TAB_VALUES })
  return (
    <ShellPage>
      <AdminHeader title="Dashboard" description="..." />
      <AdminTabs tabs={tabs} value={activeTab} onValueChange={setTab} />
    </ShellPage>
  )
}
```

For a CRUD list inside a tab: `<ListPage config={config} embedded />`.

A page with no tabs, single content block (e.g. a map): `ShellPage +
AdminHeader + ShellContent`. The detail of one record is NOT a page: it is
the list's view dialog (`dialogs.view.renderContent` → `<XDetail/>`, see
"Lists, dialogs and hubs" below).

## CRUD module: file tree and layer rule

```
src/app/admin/<module>/
├── config.tsx                    # CrudConfig<T, TFormData>  ('use client' required)
├── page.tsx                      # <ListPage config={xConfig} /> — ~5 lines
└── _components/
    └── <Module>Detail.tsx        # ContentTabs + SemanticCard/SemanticField (view dialog body)

src/app/api/<module>/route.ts        # GET list + POST create (Route Handler)
src/app/api/<module>/[id]/route.ts   # GET/PATCH/DELETE (Route Handler)
src/lib/api/<module>-client.ts       # the ONLY file that calls fetch()
```

**No `adicionar/`, `[id]/` or `[id]/editar/` routes.** View, create, edit and
delete all happen in dialogs on the list (`dialogs.view/create/edit` +
`actionsConfig.standard.delete.confirmDialog`). `telamonjs lint` fails on those
routes (`no-crud-pages`).

**Layer rule — one direction only, no exceptions:**

```
Route Handler (wraps Prisma)  →  <module>-client.ts (fetch)  →  config.tsx
```

- Route Handlers are the only code that touches Prisma.
- `<module>-client.ts` is the only code that calls `fetch()` against those
  routes.
- `config.tsx` and pages never import Prisma and never call `fetch()`
  directly — they only import the client.

See `src/app/admin/usuarios/` for a complete reference module built this
way.

## config.tsx — the CrudConfig contract

```tsx
'use client'
import { type CrudConfig, type DialogHeaderConfig } from '@telamonjs/ui'
import { getIcon } from '@/lib/icons'          // this app's registry (src/lib/icons.ts)
import { usersApi } from '@/lib/api/users-client'
import UserDetail from './_components/UserDetail'

const headerConfig: DialogHeaderConfig<User> = {
  icon: 'User', iconColor: 'blue', title: u => u.name, subtitle: u => u.email,
  gradient: 'from-blue-50 to-indigo-50',
  badge: { field: 'ativo', variants: { true: 'default', false: 'secondary' }, labels: { true: 'Ativo', false: 'Inativo' } },
}

export const usersConfig: CrudConfig<User, UserFormData> = {
  module: { name: 'users', title: 'Users', description: '...', route: '/admin/users' },
  list: {
    title: '',            // the shell breadcrumb already names the page
    description: '',
    columns,
    searchPlaceholder: 'Search...',
    serverSidePagination: true,
    infiniteScroll: true, // the default — never set it to false
    defaultPageSize: 100,
    toolbar: { counterLabel: n => (n === 1 ? 'user' : 'users') },
  },
  form: { sections, validation: validationSchema }, // sections use grid: '2'

  query: {
    queryKey: ['users'],
    // must return PaginatedResponse<T> (page, totalPages, total) — ListPage
    // defaults to infinite scroll and needs pagination metadata to drive it
    queryFn: usersApi.list,
  },

  mutations: {
    // mutationFn must resolve to { success, data? } — if the REST client
    // returns the raw entity instead, adapt it in mutationFn, not in the client
    create: {
      mutationFn: async data => ({ success: true, data: await usersApi.create(data) }),
      invalidates: [['users']],
    },
    update: {
      mutationFn: async ({ id, data }) => ({ success: true, data: await usersApi.update(id, data) }),
      invalidates: [['users'], id => ['users', id]],
    },
    delete: {
      mutationFn: async ({ id }) => {
        await usersApi.delete(id)
        return { success: true }
      },
      invalidates: [['users']],
    },
    // used by dialogs.view / dialogs.view.portal / dialogs.edit to fetch one record
    getForEdit: usersApi.getById,
    getForView: usersApi.getById,
  },

  actionsConfig: {
    standard: {
      view: { icon: getIcon('Eye'), tooltip: 'View' },
      edit: { icon: getIcon('Pencil'), tooltip: 'Edit' },
      delete: {
        icon: getIcon('Trash2'),
        tooltip: 'Delete',
        confirmDialog: { title: r => `Delete ${r.name}?`, confirmText: 'Delete', variant: 'destructive' },
      },
    },
  },
  dialogs: {
    view: { urlParam: 'view', title: 'User', headerConfig, renderContent: u => <UserDetail user={u} /> },
    edit: { urlParam: 'edit', title: 'Edit user', headerConfig },
    create: { urlParam: 'create', title: 'New user', headerConfig: { ...headerConfig, title: 'New user', badge: undefined } },
  },
}
```

Page usage: `<ListPage config={usersConfig} />` — one prop.

`create`/`update`/`delete` under `mutations` are all optional: an omitted
one resolves `{ success: false }` instead of throwing, so a read-only
module doesn't need stub mutations.

### `dialogs.view.portal` — rich view with 6+ sections

**Only for 6+ sections** (grid launcher →
one section with a side rail). With ≤5 sections the view dialog is
`renderContent` + `<XDetail/>` with `ContentTabs` — never `portal`. Wiring
it through `dialogs.view.portal` (rather than mounting `ViewPortalDialog`
standalone) gets you URL sync, row-click and the
`actionsConfig.standard.view` override for free:

```tsx
dialogs: {
  view: {
    title: u => u.name,
    portal: {
      sections: data => [
        {
          value: 'general',
          label: 'General',
          icon: 'Info',
          color: 'blue',
          content: <UserGeneralTab user={data} />,
          edit: generalSection, // a FormSection — enables inline "Save section"
        },
        {
          value: 'orders',
          label: 'Orders',
          icon: 'ShoppingCart',
          content: <UserOrdersTab userId={data.id} />, // 1:N collection: own save flow
        },
      ],
      // validation for section edits derives from `form.validation` — don't repeat it here
      onSaveSection: async (values, section) => {
        await updateMutation.mutateAsync({ id: data.id, data: values })
        return { success: true }
      },
    },
  },
}
```

`portal` and `renderContent` are mutually exclusive — if both are set,
`portal` wins and a dev warning is logged.

**`onEdit`/`onDelete`/`deleteConfirmation` do not exist on the portal** — the portal has no footer. Editing is inline per-section (via
`edit` + `onSaveSection`); deleting lives in the list's row actions.

## Exact-name traps

Field and section config use specific property names — a wrong-but-plausible
name compiles as an unused/no-op prop, not an error, so these are easy to
ship silently broken:

| You'd guess       | The real name                                     |
| ------------------ | -------------------------------------------------- |
| `title` on a field  | `label`                                            |
| `helperText`        | `description`                                      |
| `options` on `relationship`/`multiselect` | `loadField: async () => IOption[]` — `options` does not exist |
| array return from `queryFn` | `PaginatedResponse<T>` (`page`, `totalPages`, `total`) |
| `as any` on `queryFn` (client typed `sortBy?: string`) | `queryFn: asQueryFn(api.list)` from `@telamonjs/ui` |
| raw entity from mutations | `{ success: boolean, data? }` |
| no `'use client'` in `config.tsx` | required — React Query hooks need it |
| `className: 'w-full'` on a field | ignored — BaseForm is CSS Grid, use `span` (must match the section's `grid`, default `'2'`) |

## Choosing a component — quick decision trees

**Form:**
- Creating / editing a record → the `dialogs.create` / `dialogs.edit` of the
  module's `CrudConfig` (rendered from `form.sections` — no form page)
- Multi-step wizard or live preview → `ZustandForm`
- A form outside any CRUD module (settings, wizard step) → `Form` (`AdminForm`)

**List page:**
- Always start from `CrudConfig` + `<ListPage config={config} />` — one prop.
- Infinite scroll (virtualized) is the default and the
  ONLY accepted mode (`list.infiniteScroll: false` fails `telamonjs lint`).
- Only reach for `DataTable` directly when the customization is extreme.

**Shell / layout:**
- The app shell (sidebar + header + nav) → `AdminShell`.
- An internal page with several views → tabs (`ShellPage` + `AdminHeader` +
  `AdminTabs` + `useTabUrlSync`), not several standalone pages.
- A single-content page (e.g. a map) → `ShellPage` + `AdminHeader` +
  `ShellContent`.
- A single record's detail → the list's view dialog (`renderContent` →
  `<XDetail/>`), never a `[id]/page.tsx`.

- `ViewDialog` (+ `ContentTabs flush`) — ≤5 sections; wired via

## Lists, dialogs and hubs

`src/app/admin/usuarios/` is the reference. Types: `CrudConfig` in
`node_modules/@telamonjs/ui/dist/types/crud.d.ts`.

| Option | Value | Effect |
| --- | --- | --- |
| `list.infiniteScroll` | omit (default `true`) — **never `false`** | virtualized infinite list; `queryFn` must return `PaginatedResponse` (`page`, `totalPages`, `total`) |
| `list.defaultPageSize` | `100` | page size fetched per scroll step |
| `list.serverSidePagination` | `true` | search/sort/page handled by the API |
| `list.title` / `list.description` | `''` | no in-page header — the shell breadcrumb already names the page |
| `list.toolbar.counterLabel` | `n => (n === 1 ? 'usuário' : 'usuários')` | counter in the toolbar (`showCounter` default `true`, leave it) |
| `actionsConfig.standard.view/edit` | `{ icon: getIcon('Eye'/'Pencil'), tooltip }` | icon-only row actions with tooltip; never `true` |
| `actionsConfig.standard.delete` | `{ icon: getIcon('Trash2'), tooltip, confirmDialog: { title, description, confirmText, cancelText, variant: 'destructive' } }` | destructive confirm before the mutation |
| `dialogs.view.headerConfig` | `{ icon, iconColor, title, gradient, badge }` (`icon` is a STRING) | rich header, shared by view/edit; create spreads it with `title` overridden and `badge: undefined` |
| `dialogs.view.renderContent` | `item => <XDetail x={item} />` | ≤5 sections — `_components/XDetail.tsx` |
| `dialogs.view.portal` | `{ sections: data => [...] }` | 6+ sections — replaces `renderContent` (mutually exclusive) |
| `dialogs.*.urlParam` | `'view'` / `'edit'` / `'create'` (in a hub tab: the module name, e.g. `'usuario'`) | deep link + Back closes the dialog |
| `form.sections[].grid` | `'2'` | 2-column CSS grid |
| `form.sections[].fields[].span` | `'1' \| '2' \| '3' \| '12' \| 'full'` | column span (BaseForm emits `col-span-${span}`; `'2'` = full width on a `grid: '2'`) |
| `mutations.getForView` / `getForEdit` | `api.getById` (`getForEdit` may also map to `TFormData`) | record fetched when the dialog opens |

**`<XDetail/>`** (`_components/`): `'use client'`, `memo`, `ContentTabs
tabs={tabs} variant="default" defaultValue="info" flush`. Every tab body is
wrapped in a fixed height so the dialog does not resize between tabs:
`<div className={`p-6 ${contentHeight}`}>` with
`const contentHeight = 'h-[min(600px,60vh)] overflow-y-auto'`. Inside: `<div
className="grid gap-4 md:grid-cols-2">` of `SemanticCard`s with
`SemanticField`s (`Badge` for status).

**SemanticCard colours:** `blue` = identification / main data · `green` =
contact / permissions / validity · `purple` = location / stats / audit ·
`orange` = functional data / warnings.

**≤5 / 6+ decision:** a view with ≤5 sections is `ContentTabs` inside the
`ViewDialog`; 6+ is `dialogs.view.portal`. A hub (dashboard grouping several
modules, each tab `<ListPage config={x} embedded />`) with ≤5 tabs is
`ShellPage + AdminHeader + AdminTabs + useTabUrlSync`; 6+ is `AdminPortal`.

**Forbidden:** routes `adicionar/`, `[id]/`, `[id]/editar/` (CRUD lives in
dialogs) · `fetch()` anywhere but `src/lib/api/*-client.ts` · raw Radix
`Tabs`/`TabsList` (use `ContentTabs`/`AdminTabs`) · raw `<table>` (use
`ListPage`/`DataTable`) · `list.infiniteScroll: false`.

### `telamonjs lint` rules

`pnpm lint:telamonjs` (= `telamonjs lint src/app/admin`; `--json` for a report).
Exit 1 on any error; warnings only inform. Values the linter cannot resolve
statically (spreads of imported objects, computed keys) are never reported.

| Rule | Severity | Fires when |
| --- | --- | --- |
| `list-infinite` | error | `list.infiniteScroll === false` |
| `list-title-empty` | warning | `list.title` or `list.description` is a non-empty string |
| `list-pagesize` | warning | `list.defaultPageSize` missing or `< 50` |
| `actions-icon-tooltip` | error | `standard.view/edit/delete` is `true` or lacks `icon`/`tooltip`; `delete` lacks `confirmDialog` |
| `view-header` | error / warning | `dialogs.view` has neither `headerConfig` nor `renderHeader` / `headerConfig` lacks `icon` or `title` |
| `view-content` | error | `dialogs.view` has neither `renderContent` nor `portal` |
| `view-tabs` | error | the `renderContent` component imports `Tabs`/`TabsList` from Radix or the lib |
| `dialog-height` | warning | the component uses `ContentTabs` without `h-[min(` in its text |
| `form-span` | error | a field `span` outside `'1' \| '2' \| '3' \| '12' \| 'full'` (e.g. `col-span-2`) |
| `no-fetch-in-config` | error | a `fetch(...)` call inside `config.tsx` |
| `no-crud-pages` | error | `adicionar/page.tsx`, `[id]/page.tsx` or `[id]/editar/page.tsx` next to a `config.tsx` |
| `portal-size` | warning | the `renderContent` component has more than 5 `ContentTabs` tabs |
| `hub-tabs` | warning | a page calls `useTabUrlSync` with more than 5 tabs (use `AdminPortal`) |
| `no-raw-link` | error | `<a>`/`<Link>` (next/link) whose direct JSX parent has no `asChild` — navigation is `<Button asChild><Link …/></Button>`; `<a target="_blank">`, `download` and `mailto:`/`tel:` pass |
| `icons-from-registry` | error | `config.tsx` imports from `lucide-react` (type-only imports pass) — use `getIcon('Name')` from `@/lib/icons` |
| `button-icon-size` | warning | a capitalized JSX child of `<Button>` (not `asChild`) with a literal `className` lacking `h-4 w-4`/`size-4` — icons in Button use `mr-2 h-4 w-4` |
| `i18n-literal-in-config` | error | in an app with `messages/`, a `title`/`label`/`header`/`placeholder`/`description` in `config.tsx` is a pt-BR string literal — use `msg('<key>')` |
| `i18n-untranslated` | warning | a key in `messages/en.json` or `messages/es.json` has the same value as in `pt-BR.json` (a stub nobody translated) |

The linter only reports what it can prove in the AST (spreads, computed values and unresolvable components are skipped, never flagged). Per-file escape for a justified exception: `// telamonjs-lint-disable-file <rule>[, <rule>]` at the top of the *flagged* file (no rule = all rules) — always with a one-line reason next to it (e.g. a legitimate `[id]/page.tsx` for a long timeline).

## Brand

Assets the shell and the browser expect (swap the files, keep the names):
`public/logo.svg` (wordmark, light theme), `public/logo-dark.svg` (wordmark for
the dark theme), `public/logo-mark.png` (square mark, collapsed sidebar) and
`src/app/icon.png` (favicon via the Next.js metadata convention). The scaffold
ships placeholders (`public/logo.png`, `public/icon-compact.png`) wired in
`LayoutProviders.tsx` — replace them with the files above and update the props.

`AdminShell` takes `logoUrl`, `compactLogoUrl` and `logoHeight` (px). There is no
theme-aware logo prop: swap it yourself by observing the `dark` class on
`<html>` with a `MutationObserver`:

```tsx
const [isDark, setIsDark] = useState(false)
useEffect(() => {
  const root = document.documentElement
  const read = () => setIsDark(root.classList.contains('dark'))
  read()
  const obs = new MutationObserver(read)
  obs.observe(root, { attributes: true, attributeFilter: ['class'] })
  return () => obs.disconnect()
}, [])
<AdminShell logoUrl={isDark ? '/logo-dark.svg' : '/logo.svg'} compactLogoUrl="/logo-mark.png" logoHeight={28} … />
```

Theme = tokens in `src/styles/globals.css` (`--primary`, `--muted-foreground`, …).
Never hardcode palette colors in components (`bg-green-600`, `text-gray-500`):
status is `<Badge variant="…">`, secondary text is `text-muted-foreground`,
emphasis is `text-primary`, danger is `text-destructive`.

## i18n

This app ships multi-locale from birth (`pt-BR` | `en` | `es`, default
`pt-BR`) via `next-intl`. Three rules:

1. **`config.tsx` (no hooks available) uses `msg('usuarios.title')`** from
   `@telamonjs/ui/i18n` for every `I18nText`-typed slot (`module.title`,
   `list.searchPlaceholder`, column `header`, `formSections[].label/description`,
   field `label/placeholder/description`, `dialogs.*.title/description`,
   `headerConfig.title`, `badge.labels`, action `tooltip`,
   `confirmDialog.description/confirmText/cancelText`). Text rendered inside a
   `cell`/JSX callback uses `<Msg k="usuarios.roleAdmin" />` instead (a real
   component, so it can call the underlying hook). Per-row functions (a
   `headerConfig.title: u => u.name`, a `confirmDialog.title: row => …`) return
   data, not chrome text. See `src/app/admin/usuarios/config.tsx` for the
   worked example.
2. **Client components** (`'use client'`) use `useTranslations()` /
   `useFormat()` / `useTelamonjsT()` (app namespaces vs. the library's `telamonjs.*`).
3. **Server components** use `getTranslations()` from `next-intl/server`.

**Every new message key goes in all three files**, mirrored:
`messages/pt-BR.json`, `messages/en.json`, `messages/es.json`. There is no
build-time guard for missing keys in this template (unlike the library's own
message tree) — a missing key falls back to the raw key string at runtime, so
diff the three files by hand when you add one.

The locale is resolved once per request in `src/i18n/request.ts`
(`NEXT_LOCALE` cookie → `Accept-Language` → `pt-BR`) and merged with the
library's own `telamonjs.*` messages (`@telamonjs/ui/i18n`'s
`telamonjsMessages`). `LocaleSwitcher` (rendered by `AdminShell` by default)
writes the cookie and calls `router.refresh()`. Zod's error map speaks the
active locale via `setupZodLocale(locale)`, wired in `app-providers.tsx`.

## Authentication

- Config: `src/auth.ts` — the app's own `authorize()` plus
  `createAuthCallbacks()` from `@telamonjs/auth/next` (the session contract:
  `session.user.role` is a `RoleInfo` `{ id, name, code }`, so role checks read
  `role.code`; `permissions` is a `string[]`). Compose over those callbacks
  instead of replacing them; the package README covers session revocation
  and stale-role refresh
- Layout guard: `src/app/admin/layout.tsx` (calls `auth()`, redirects unless
  `session?.user` exists — check the user, never just `session`: on an auth
  error `auth()` returns a truthy error body)
- Client hook: `src/hooks/use-session.ts`
- Middleware: `src/middleware.ts` (Node runtime) protects `/admin/*`; `/api/*` is not matched —
  each Route Handler does its own `getCurrentUser()` / role check (see
  `src/app/api/usuarios/route.ts`)
- Seed user: `admin@example.com` / `12345` / role `ADMIN`
