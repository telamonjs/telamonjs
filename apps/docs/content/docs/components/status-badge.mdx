Reusable badge component for "new"/"beta" tags, status labels and trend
percentages, configured per call.

<StatusBadgePreview />

<Callout type='info' title='Not the same as DetailStatus'>
  `StatusBadge` is a **base component** configured per call. `DetailStatus`
  is a separate detail-page component driven by a `statusConfig` map; it
  renders the `Badge` primitive, not `StatusBadge`.
</Callout>

---

## Basic Usage

```tsx
import { StatusBadge } from '@telamonjs/ui'

export default function MyComponent() {
  return <StatusBadge type='status' label='Active' variant='success' />
}
```

<Callout type='warn' title='There is no `status` prop'>
  The component is driven by `type` + `label` + `variant`, and `icon` takes a rendered `ReactNode`,
  not a component reference.
</Callout>

## Props

```typescript
type BadgeType = 'new' | 'beta' | 'custom' | 'status' | 'trend'
type BadgeVariant =
  | 'default'
  | 'secondary'
  | 'destructive'
  | 'outline'
  | 'success'
  | 'warning'

interface StatusBadgeProps {
  type?: BadgeType // Badge kind — drives default label/variant (default: 'custom')
  label?: string // Display text (overrides the type's default label)
  variant?: BadgeVariant // Color variant (overrides the type's default variant)
  value?: number // Percentage value, only used when type='trend'
  icon?: React.ReactNode // Icon element, already rendered (e.g. <Check className="h-3 w-3" />)
  size?: 'sm' | 'md' | 'lg' // Badge size (default: 'sm')
  className?: string // Additional classes
}
```

**Type → default label/variant:**

| `type`     | Default label | Default variant |
| ---------- | -------------- | ---------------- |
| `new`      | Localized "New" (`common.create`) | `secondary` |
| `beta`     | "Beta"          | `outline`         |
| `custom`   | (none — pass `label`) | `secondary` |
| `status`   | (none — pass `label`) | `default`   |
| `trend`    | (none — renders `value`%) | `secondary` |

Any of these can be overridden by passing an explicit `label`/`variant`.

<Callout type='info' title='No auto-coloring from status strings'>
  `StatusBadge` does **not** infer a color from the text of `label` (e.g. the string `"failed"` does
  not automatically turn the badge red). You always pass `variant` explicitly — build your own
  `Record<Status, variant>` mapping if you need per-status colors (see
  [Complete Example](#complete-example) below).
</Callout>

## Variants

### Status Badge

```tsx
<StatusBadge type='status' label='Active' variant='success' />
<StatusBadge type='status' label='Pending' variant='warning' />
<StatusBadge type='status' label='Failed' variant='destructive' />
<StatusBadge type='status' label='Draft' variant='outline' />
```

### New / Beta

```tsx
<StatusBadge type='new' />   {/* "New" (localized), secondary variant */}
<StatusBadge type='beta' />  {/* "Beta", outline variant */}
```

### Trend

```tsx
<StatusBadge type='trend' value={15.5} />   {/* Green up-arrow, "15.5%" */}
<StatusBadge type='trend' value={-4.2} />   {/* Red down-arrow, "4.2%" */}
<StatusBadge type='trend' value={0} />      {/* Muted dash, "0%" */}
```

Trend color and arrow direction are derived automatically from the sign of `value`.

### Custom

```tsx
<StatusBadge type='custom' label='VIP' variant='outline' />
```

## Complete Example

```tsx title="components/order-status.tsx"
import { StatusBadge } from '@telamonjs/ui'
import { Check, Clock, AlertCircle, X, Package } from 'lucide-react'

type OrderStatus = 'pending' | 'processing' | 'shipped' | 'delivered' | 'cancelled'

interface OrderStatusBadgeProps {
  status: OrderStatus
}

const statusConfig: Record<
  OrderStatus,
  {
    variant: 'default' | 'secondary' | 'destructive' | 'outline' | 'success' | 'warning'
    icon: React.ReactNode
    label: string
  }
> = {
  pending: { variant: 'warning', icon: <Clock className='h-3 w-3' />, label: 'Pending' },
  processing: { variant: 'outline', icon: <Package className='h-3 w-3' />, label: 'Processing' },
  shipped: { variant: 'outline', icon: <Package className='h-3 w-3' />, label: 'Shipped' },
  delivered: { variant: 'success', icon: <Check className='h-3 w-3' />, label: 'Delivered' },
  cancelled: { variant: 'destructive', icon: <X className='h-3 w-3' />, label: 'Cancelled' },
}

export default function OrderStatusBadge({ status }: OrderStatusBadgeProps) {
  const config = statusConfig[status]

  return <StatusBadge type='status' label={config.label} variant={config.variant} icon={config.icon} />
}
```

## Best Practices

1. **Consistent mapping** - Build one `Record<Status, variant>` map and reuse it across the app (see Complete Example)
2. **Appropriate variants** - Match color to meaning (`success` = green, `destructive` = red)
3. **Icons optional** - Pass a rendered `ReactNode`, only add when it clarifies meaning
4. **Size consistency** - Use the same `size` within the same context
5. **Explicit variant** - There is no auto-coloring from label text; always pass `variant`
6. **Text clarity** - Use clear, concise labels
7. **Accessibility** - Don't rely only on color (use text + icon)

## StatusBadge vs DetailStatus

| Feature         | StatusBadge (Base)      | DetailStatus (Higher-level) |
| --------------- | ------------------------ | ---------------------------- |
| **Use case**     | General-purpose          | Detail pages specifically    |
| **Location**     | Tables, cards, anywhere  | Detail pages only            |
| **Config**       | Props per call (`type`/`label`/`variant`) | External `statusConfig` map (`status`/`statusConfig` props) |
| **Import from**  | `@telamonjs/ui`          | `@telamonjs/ui` or `@telamonjs/ui/detail` |

**Decision:**

- ✅ Use **StatusBadge** - Tables, cards, lists, forms
- ✅ Use **DetailStatus** - Detail/view pages with a shared `statusConfig` map
