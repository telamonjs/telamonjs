New `telamonjs add admin <audit|parameters> [--dry-run] [--cwd <dir>]`: scaffolds an admin-kit module into an app generated by `telamonjs create`, single app or monorepo. `audit` adds an `AuditLog` model, the `audit.read` permission, `GET /audit` (filters `entityType`, `entityId`, `userId`, `action`, `from`/`to`) and `GET /audit/:id`, and a read-only `/admin/auditoria` list with an `AuditChangesViewer` view dialog; the monorepo API records every mutation through `createAuditInterceptor`, the single app's users and roles Route Handlers call a new `src/lib/audit.ts`. `parameters` adds a typed `Parameter` model, `parameters.read`/`parameters.write`, a CRUD API, a typed getter, an unauthenticated `GET /parameters/public?keys=` for public parameters and a `/admin/parametros` page. Each run appends a marked Prisma block (or its own file in a multi-file schema), adds the permission codes to `rbac.ts`, a menu entry with `permission` and pt-BR/en/es messages; it is idempotent, never migrates, and refuses apps that are not template-shaped (adopt the runtime pieces there). The templates' users module now revokes a user's sessions (`sessionsRevokedAt`) when their password changes.

Fix in the monorepo template: the web API client now shows the API's error message. The superjson middleware wraps error bodies too (`{ json: { message } }`), so the client fell back to its generic text.
