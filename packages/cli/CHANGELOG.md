# Changelog

## 1.4.2

### Patch Changes

- 7289ce5: Generated apps:

  - The seed creates the default admin only on an empty database and never changes an existing account. In production the first admin's password comes from `SEED_ADMIN_PASSWORD`, and the container stops if the seed fails.
  - `docker-compose.prod.yml` reads `NEXTAUTH_SECRET` and `DB_PASSWORD` (plus `SEED_ADMIN_PASSWORD` on an empty database) from the environment and binds the database port to `127.0.0.1`.
  - `next.config.js` starts with an empty `images.remotePatterns`; add the hosts your images come from. Existing apps: replace `hostname: '**'` with those hosts.
  - The Docker image builds again (the Prisma schema is copied before install) and includes the migrations; the entrypoint retries `prisma migrate deploy` until the database answers. `.gitignore` no longer ignores `prisma/migrations/**/*.sql`.
  - `telamonjs db dump` keeps `database/dumps/` out of git.
  - Granting roles or permissions (user roles, invitations, role permissions) is limited to permissions the acting user holds; only an admin grants the `admin` role, and a user can't edit another with more access.
  - Deleting a role takes effect on its holders' next request.
  - The single-app audit log records the client IP added by the reverse proxy (`TRUSTED_PROXY_HOPS`, default 1).
  - `telamonjs generate crud` emits Route Handlers that require `<name>.read` / `<name>.write`, registers both codes in `src/rbac.ts` (run the app's `db:seed` script afterwards), and stops in apps created before CLI 1.2.0, which have no RBAC.

## 1.4.1

### Patch Changes

- 9999637: `generate crud` finds the Prisma schema in more places: `package.json#prisma.schema`
  (file or folder), a multi-file `prisma/schema/` folder (`prismaSchemaFolder`, nested
  folders included) and the monorepo's `packages/shared/prisma`, also when run from
  `apps/web` inside a pnpm workspace. When schema detection is on and the schema or the
  model is missing, it now stops with an error that lists where it looked (or which
  models the schema has) instead of quietly generating placeholder fields;
  `--no-prisma-schema` still generates generic fields on purpose.

  The schema parser no longer truncates a model at a `}` inside a string (`@default("{}")`)
  or a comment, ignores commented-out models, reads `@default(cuid())` whole, and matches
  `--model` literally instead of as a regular expression.

  Formatting the generated files works for paths with spaces (Prettier gets an argument
  list instead of a shell string), never downloads Prettier when the app doesn't have it,
  and a failure now prints Prettier's reason instead of a generic "not found".

  The build fails when `dump.sh` or `restore.sh` cannot be copied into `dist`, instead of
  publishing a CLI whose `db dump` / `db restore` break at runtime.

  When the automatic setup of `create` (Docker, migrate, seed) fails, it prints the error and
  a hint, and shows the manual steps instead of claiming the app is ready.

## 1.4.0

### Minor Changes

- 8df1d26: `telamonjs add admin invitations`: email invitations for apps generated by `telamonjs create`, in both layouts. Adds an `Invitation` Prisma model (only the sha256 of the link's token is stored, 7-day expiry, `EXPIRED` computed on read), `invitations.read`/`invitations.write`, `GET/POST /invitations`, `POST /invitations/:id/resend` (rotates the token), `PUT /invitations/:id/revoke`, and the public `GET /invitations/by-token/:token` and `POST /invitations/accept` (creates the user with the invited roles and marks the invitation accepted in one transaction; every unusable token gets the same 410). The web side gets `/admin/convites` (invite dialog, resend/revoke row actions) and a public `/convite/<token>` page that creates the account and signs in. Mail goes through a port the app implements, console-only by default: `sendMail()` in `src/lib/mail.ts`, or the `MAIL_SENDER` provider of `apps/api/src/modules/mail` in the monorepo. The accept link is built from `NEXTAUTH_URL`, noted in `.env.example`.

## 1.3.0

### Minor Changes

- 19a0023: New `telamonjs add admin <audit|parameters> [--dry-run] [--cwd <dir>]`: scaffolds an admin-kit module into an app generated by `telamonjs create`, single app or monorepo. `audit` adds an `AuditLog` model, the `audit.read` permission, `GET /audit` (filters `entityType`, `entityId`, `userId`, `action`, `from`/`to`) and `GET /audit/:id`, and a read-only `/admin/auditoria` list with an `AuditChangesViewer` view dialog; the monorepo API records every mutation through `createAuditInterceptor`, the single app's users and roles Route Handlers call a new `src/lib/audit.ts`. `parameters` adds a typed `Parameter` model, `parameters.read`/`parameters.write`, a CRUD API, a typed getter, an unauthenticated `GET /parameters/public?keys=` for public parameters and a `/admin/parametros` page. Each run appends a marked Prisma block (or its own file in a multi-file schema), adds the permission codes to `rbac.ts`, a menu entry with `permission` and pt-BR/en/es messages; it is idempotent, never migrates, and refuses apps that are not template-shaped (adopt the runtime pieces there). The templates' users module now revokes a user's sessions (`sessionsRevokedAt`) when their password changes.

  Fix in the monorepo template: the web API client now shows the API's error message. The superjson middleware wraps error bodies too (`{ json: { message } }`), so the client fell back to its generic text.

## 1.2.0

### Minor Changes

- 5f74898: New apps ship database-backed RBAC. The template's Prisma schema replaces the `RoleName` enum with the RBAC tables of `@telamonjs/permissions` (`Role`, `Permission`, `RolePermission`, `UserRole`); `User` gets `roles`, `active` (was `ativo`), `accessChangedAt` and `sessionsRevokedAt`. The seed syncs a code-defined permission catalog (`src/rbac.ts`) with `diffPermissionCatalog`, and creates a built-in `admin` role holding every permission plus the admin user with it. Sign-in materializes roles and permission codes into the session token; on every renewal `sessionState` signs out deactivated or revoked users and refreshes stale claims. The single app gets `/admin/papeis` (role CRUD and a `PermissionMatrix` tab), multi-role assignment and activate/deactivate in `/admin/usuarios`, a `PermissionsProvider` around the shell, menu and CrudConfig permissions, and `requirePermission()` in every Route Handler. The monorepo moves `src/rbac.ts` to `packages/shared` (`./rbac`) and replaces the API's `AdminGuard`/`@AdminOnly()` with a global `createPermissionsGuard` and `@Permissions(...)`, plus a `roles` module (CRUD, `GET roles/matrix`, grant/revoke). Existing apps are unaffected.

## 1.1.6

### Patch Changes

- 213e737: `CrudConfig` takes API clients and actions as they are typed, so the `asQueryFn` / `asCreateFn` wrappers can go:

  - **`query.queryFn` receives `ListQueryParams`**, the params ListPage actually sends: `page`, `pageSize`, `search?`, `sortBy?`, `sortOrder?`, `filters?`, with `sortBy` always ONE column as a `string` (the list reduces its `SortField[]` sort to the first field before calling `queryFn`, as it always did). A client typed `(params?: { page?: number; sortBy?: string; status?: string; ... })` or `(params: Record<string, unknown>)` is now a `queryFn` as is: `queryFn: api.list`. `ListQueryParams` is exported. `asQueryFn` keeps working (an unchecked cast, for a client that still does not fit, such as one whose result is not typed `PaginatedResponse<T>`).
  - **`ListQueryState.params`** (what `toolbarContent` and `list.onExport` get) now holds the params exactly as `queryFn` gets them, as its docs always said: `sortBy` is the first sort column's string with its `sortOrder`, not the `SortField[]`. The full sort is still in `state.sorting`. An `onExport` that passed `params` to its client sent an array as `sortBy` before; it now sends the column.
  - **`CrudConfig<T, TFormData, TResult = T>`** (and `MutationsConfig`): a third type argument says what `create`/`update` resolve in `data`, the entity by default. Actions that answer `ActionResponse<{ id: string }>` or `ActionResponse<unknown>` compile with `CrudConfig<Row, RowFormData, { id: string }>` (or `unknown`) instead of a cast, and `onSuccess(result)` gets that type. Configs that return the entity change nothing and keep a typed `onSuccess`. `CrudConfigWithAnyForm<T>` (what `ListPage` takes) accepts every `TResult`.

  ### Upgrading

  Code that calls `config.query.queryFn` itself, or a helper typed against `(params: PaginationParams) => ...`, no longer compiles (`Type 'SortField[]' is not assignable to type 'string'`, or `Argument of type 'CrudConfig<...>' is not assignable to parameter of type 'CrudConfig<...> & { query: { queryFn: (params: PaginationParams) => ... } }'`). The fix is one type name: use `ListQueryParams` where the helper types the `queryFn` parameter.

  ```diff
  -import type { PaginationParams, PaginatedResponse } from '@telamonjs/ui'
  +import type { ListQueryParams, PaginatedResponse } from '@telamonjs/ui'

   export function withExternalFilters<T>(
  -  config: T & { query: { queryKey: readonly unknown[]; queryFn: (params: PaginationParams) => Promise<PaginatedResponse<any>> } },
  +  config: T & { query: { queryKey: readonly unknown[]; queryFn: (params: ListQueryParams) => Promise<PaginatedResponse<any>> } },
     extraParams: Record<string, unknown>
   ): T {
     ...
  -      queryFn: (params: PaginationParams) => originalQueryFn({ ...params, ...cleaned } as PaginationParams),
  +      queryFn: (params: ListQueryParams) => originalQueryFn({ ...params, ...cleaned } as ListQueryParams),
  ```

  The same goes for a scoped `queryFn: (params: PaginationParams) => base.query.queryFn({ ...params, filters })` and for a test that calls `config.query.queryFn(params)` with `params: PaginationParams`. An API client typed `(params: PaginationParams)` keeps working as a `queryFn`; only code that _calls_ one needs the new name.

  Then the wrappers can be deleted: `queryFn: asQueryFn(api.list)` → `queryFn: api.list`; `mutationFn: asCreateFn<Row, RowFormData>(createAction)` whose action resolves `{ success, data?: { id } }` → `mutationFn: createAction` plus `CrudConfig<Row, RowFormData, { id: string }>`. A component or helper that receives such a config types it `CrudConfigWithAnyForm<T>` rather than `CrudConfig<T, TFormData>` (which expects the entity in `data`).

## 1.1.5

### Patch Changes

- 3fc8c80: `CrudConfig` accepts more of what apps already write, so these casts and wrappers can go:

  - **`mutations.getForEdit` may resolve the entity** (`TFormData | T`), so `getForEdit: api.getById` compiles without `as any` or an `asGetForEdit` wrapper. The edit form reads the fields it declares by name, as it always did.
  - **`headerConfig.iconColor` and `headerConfig.gradient` may be functions of the record** (`iconColor: r => (r.active ? 'green' : 'gray')`). Before, a function only compiled with a cast and was silently ignored at runtime; now it is resolved, falling back to `gray` and the default gradient when there is no record (the create dialog).
  - **`dialogs.*.defaultValues` accepts form-only keys** (`Partial<T> & Record<string, unknown>`): a create dialog can preset `categoryId` without a cast; keys of `T` keep their type.
  - **A `crud` field's `listFields` takes SubList columns** (`{ header, accessorKey | accessorFn, cell? }`, the `SubListField` type), the shape the sub-list always rendered, instead of `FormField` only. Drop the `as any` on each entry (and any `enableGlobalFilter` on it: the sub-list searches every column anyway).

  These casts are not needed with the current types and can simply be deleted: `columns: columns as any` (`ColumnDef<T>[]` is accepted), `headerConfig.badge.field: '...' as any` and `badgeField()` (`field` is a `string`), `mutations: { getForView } as any` and `readOnlyMutations()` (every mutation is optional). A local `asQueryFn` copy can be replaced by the one `@telamonjs/ui` exports.

## 1.1.3

### Patch Changes

- eb8e276: `telamonjs db dump` / `db restore` report failures correctly. A failing `pg_dump` used to print
  "Dump created successfully" and leave an empty `.sql.gz` that `db restore` then offered as a valid
  backup; it now fails, removes the partial file and says so. In `db restore`, a failed connection
  or a corrupt dump now prints its error message (under `set -e` the checks never ran), and a failed
  `prisma migrate deploy` after a successful restore only warns, as documented, instead of making the
  whole restore exit as failed.
- 5abed37: Raise the minimum versions of runtime dependencies to the current minors (no peer range changes).

  - `@telamonjs/ui`: `recharts` `~3.3.0` → `~3.11.0`; the `@radix-ui/react-*` primitives,
    `@tiptap/*` `^3.35.0`, `react-aria` `^3.53.1`, `react-stately` `^3.51.0`, `zustand` `^5.1.0`,
    `date-fns` `^4.4.0`, `dompurify` `^3.4.18`, `react-grid-layout` `^2.3.0`, `react-is` `^19.3.1`,
    `@tanstack/react-virtual` `^3.14.26`, `@uiw/react-textarea-code-editor` `^3.1.3` and
    `@vis.gl/react-google-maps` `^1.10.2`.
  - `@telamonjs/cli`: `fs-extra` `^11.4.1`. Apps created by `create-telamonjs-app` pin the same
    updated versions (`@radix-ui/*`, `@auth/prisma-adapter`, `date-fns`, `zustand`, `postcss`,
    `autoprefixer`, `prettier`, `prettier-plugin-tailwindcss`, `tsx` and friends).

- 4ea79f7: Export peers are lazy and optional.

  - `papaparse` is no longer a peer: `exportToCSV` writes RFC 4180 CSV itself (UTF-8 BOM, CRLF, same quoting). Columns that share a header no longer collapse into one.
  - `jspdf` and `jspdf-autotable` are now **optional** peers (`peerDependenciesMeta`), loaded with `import()` only when a PDF is exported. Without them the app still builds, and the PDF export fails with a localized toast naming the packages to install (new message `data.exportMissingPeer`) instead of a module-not-found error. `exportToPDF` returns a `Promise<void>` (it returned `void`) and rejects with an error naming both packages.
  - `scripts/check-lazy-deps.mjs` now fails the build if any file in `dist/` statically imports an optional peer.

  **Apps:** nothing to change; PDF export keeps working where `jspdf` + `jspdf-autotable` are installed. Apps that never export PDF can drop them, and every app can drop `papaparse` and `@types/papaparse` unless it uses them directly. New apps from `create-telamonjs-app` keep the `jspdf` pair and no longer list `papaparse`.

- 21eef48: Excel export no longer depends on SheetJS: the `xlsx` peer is gone. npm only carries `xlsx` 0.18.5, flagged by CVE-2023-30533 (prototype pollution) and CVE-2024-22363 (ReDoS), and the fixed builds are published outside the registry. `exportToExcel` now writes the workbook itself (OOXML parts, zipped with the platform `CompressionStream`), with no dependency at all.

  - Same output: columns, headers, cell values, filename, sheet name and 10–50 character column widths. The header row is now really bold on a light gray fill (SheetJS community silently ignored that styling).
  - Sheet names follow Excel's rules instead of throwing: at most 31 characters, `\ / ? * [ ] :` become spaces.
  - `exportToExcel` and `exportTableData` return a `Promise<void>` that resolves once the download starts (they returned `void`); await it to catch failures.

  **Apps:** nothing to change. `xlsx` can be removed from the app's dependencies (`pnpm remove xlsx`) unless the app uses it directly. New apps from `create-telamonjs-app` no longer list it.

## 1.1.0

### Minor Changes

- d2a50d7: New `telamonjs link [--ui <path>] [--package <path>]` and `telamonjs unlink [--package <path>]` commands switch an app between the published `@telamonjs/ui` and a local TelamonJS checkout, so apps no longer carry their own script. `link` follows the documented recipe: an injected `file:` dependency on the checkout's `packages/ui`, plus the required `pnpm.overrides["@telamonjs/logger"]` link in the workspace root's `package.json`. `unlink` removes both and restores the range committed at `HEAD`, else `^` plus the latest published version, never the checkout's own version. The edited `package.json` is `apps/web/package.json` when it exists, else `./package.json`. Neither command runs `pnpm install`.

  Monorepo template: `@telamonjs/cli` is now a root devDependency; `telamonjs:link`/`telamonjs:unlink` and the husky hooks call the command, and `scripts/telamonjs-mode.mjs` is gone. `post-commit` relinks when `node_modules` still holds the injected checkout, and `pre-commit` also stages the root `package.json`. Both templates' `next.config.js` treat a `file:` range as link mode too.

## 1.0.3

### Patch Changes

- 941da22: Scaffolded apps now use `@telamonjs/auth` instead of hand-rolled auth on raw `@auth/core`. The NextAuth config (single app and monorepo `apps/web`) uses the `jwt` and `session` callbacks of `createAuthCallbacks()` from `@telamonjs/auth/next` directly. `authorize()` returns the session contract: `role` is a `RoleInfo` and `permissions` is an array, and `authTime`/`accessAt` are stamped at login. The monorepo API's `JwtAuthGuard` extends `createJwtAuthGuard()` from `@telamonjs/auth/nest`, and its `resolveUser` still rejects inactive or deleted users and reads the role from the database. `@Public()` now comes from the package, and the API no longer depends on `@auth/core` directly (it is a peer of `@telamonjs/auth`). Role checks read `role.code`.

  Monorepo husky hooks: `post-commit` only relinks `@telamonjs/ui` when `node_modules` still resolves to the local checkout. Before, every pnpm-installed package counted, because each one is a symlink. `pre-commit` now aborts the commit when the lockfile update fails, and shows the error.
