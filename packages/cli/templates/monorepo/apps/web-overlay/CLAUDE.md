# CLAUDE.md — {{scope}}/web

Next.js 15 (App Router) app generated by `telamonjs create --monorepo`. See
[AGENTS.md](./AGENTS.md) for the shell/AdminShell, CrudConfig and
`telamonjs lint` conventions — unchanged from the single-package template.

## What moved out of this app

- **Prisma.** There is no `prisma/` directory and no `src/lib/prisma.ts`
  here anymore — the schema and the singleton client live in
  `../../packages/shared`. Import it as `{{scope}}/shared/prisma`.
- **The usuarios and roles routes.** `src/app/api/usuarios/**` and
  `src/app/api/roles/**` are gone; they live in `apps/api` (NestJS,
  `/v1/usuarios`, `/v1/roles`), which enforces the permissions
  (`@Permissions`). `src/lib/api/{usuarios,roles}-client.ts` call it through
  `src/lib/api/client.ts` (SuperJSON, `credentials: 'include'`) instead of
  `fetch()`ing a local Route Handler.
- **`src/rbac.ts`** (permission catalog, `loadAccess`) is
  `{{scope}}/shared/rbac` — `src/auth.ts` reads the user's roles and
  permissions from it at sign-in and when the token goes stale.
- The only Route Handler left in `src/app/api/` is `auth/[...nextauth]` —
  the NextAuth session is still issued here; `apps/api` only decodes it
  (`apps/api/CLAUDE.md`).

## Permissions

`src/lib/permissions.ts` (`can`) feeds the `PermissionsProvider` in
`LayoutProviders.tsx`: menu items with `permission` and CrudConfigs with
`permissions` hide what the session can't do. That is UX only — `apps/api`
checks the same codes on every route.

## Ports

| Service | Port |
|---|---|
| Next.js (`pnpm dev`, from the root) | {{appPort}} |
| API (`pnpm dev:api`, from the root) | {{apiPort}} |

`next.config.js` proxies `/v1/*` to the API port in dev (no Traefik
required locally) and lists `{{scope}}/shared` in `serverExternalPackages`
(it uses Prisma/Node built-ins — never bundle it).
