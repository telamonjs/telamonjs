# @telamonjs/cli

[![npm](https://img.shields.io/npm/v/@telamonjs/cli.svg)](https://www.npmjs.com/package/@telamonjs/cli) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](https://github.com/telamonjs/telamonjs/blob/main/LICENSE)

Scaffolding for TelamonJS apps: create a ready-to-run Next.js admin wired to
`@telamonjs/ui`, generate CRUD modules from your Prisma schema, add admin-kit
modules (audit log, system parameters), lint admin modules against the
framework conventions and manage database dumps.

## Create an app

```bash
npx -p @telamonjs/cli create-telamonjs-app my-admin
# or, with the CLI installed globally
pnpm add -g @telamonjs/cli && telamonjs create my-admin
```

`create-telamonjs-app <name>` is the same as `telamonjs create <name>`. Run
`create-telamonjs-app` or `telamonjs` with no arguments (or `telamonjs wizard`)
to get the **wizard**: it asks for the name, the database, the port, single app
or monorepo, and whether to install dependencies and initialize git.

| Option | Default | What it does |
| --- | --- | --- |
| `-p, --provider <provider>` | `postgresql` | Database provider: `postgresql` or `mysql` |
| `--port <port>` | `3001` | Development server port |
| `--monorepo` | off | pnpm monorepo (`apps/web`, `apps/api`, `apps/jobs`, `packages/shared`) instead of a single Next.js app |
| `--skip-install` | off | Skip dependency installation |
| `--skip-git` | off | Skip git initialization |

You get a reference `CrudConfig` module, the `AdminShell` layout with a typed
menu, NextAuth v5 sign-in, database-backed roles and permissions (role CRUD,
a permission matrix, multi-role users, permissions in the JWT with
`@telamonjs/permissions`), a Prisma schema with docker-compose for the
database, the Tailwind preset and pt-BR (default), en and es messages with a
language switcher. The CLI prints the remaining steps (database, env, seed)
when it finishes. The app pins `@telamonjs/cli` as a devDependency, so the
commands below also run locally, for example `pnpm telamonjs lint`.

## Generate CRUD from Prisma

```bash
telamonjs generate crud products --model Product
```

Reads the Prisma schema (`package.json#prisma.schema`, `prisma/schema.prisma`, a
multi-file `prisma/schema/` folder, or a monorepo's `packages/shared/prisma`;
it stops with an error when the schema or the model is missing), maps the fields to the field system and writes
`config.tsx`, the list `page.tsx`, a detail component for the view dialog, a
REST client and its route handlers, plus the module's i18n messages. Create,
edit and view open in dialogs, with no extra routes. The route handlers require
`<name>.read` (GET) and `<name>.write` (POST, PATCH, DELETE); the command adds
both to `PERMISSIONS` in `src/rbac.ts` (run `pnpm db:seed` so the admin role
gets them); in an app without `requirePermission()` in `src/lib/auth.ts` it
stops before writing anything. It also adds the module to the menu; the menu entry and the
`CrudConfig` check the same codes. Missing arguments are asked interactively. Options: `-m, --model`,
`-p, --path` (default `src/app/admin/<name>`), `--no-prisma-schema`,
`--no-update-menu`, `-f, --force` (overwrite the module's messages block).
`telamonjs g` is an alias of `generate`.

## Admin kit: add admin

```bash
telamonjs add admin audit [--dry-run] [--cwd <dir>]
telamonjs add admin parameters
telamonjs add admin invitations
```

Adds a ready-made admin module to an app generated by `telamonjs create`, in
either layout (single app or monorepo):

- **`audit`**: an `AuditLog` Prisma model, the `audit.read` permission, a
  read-only `/admin/auditoria` list whose view dialog renders the changes with
  `AuditChangesViewer`, and `GET /audit` (filters `entityType`, `entityId`,
  `userId`, `action`, `from`/`to`) plus `GET /audit/:id`. In the monorepo it
  registers `createAuditInterceptor` as a global interceptor; in the single app
  the users and roles Route Handlers call `audit()` from `src/lib/audit.ts`.
- **`parameters`**: a `Parameter` Prisma model (typed text values: `STRING`,
  `NUMBER`, `BOOLEAN`, `JSON`), `parameters.read`/`parameters.write`, a CRUD API,
  a typed getter, an unauthenticated `GET /parameters/public?keys=a,b` for the
  parameters marked public, and a `/admin/parametros` page.
- **`invitations`**: an `Invitation` Prisma model (only the token's sha256 is
  stored; links expire after 7 days), `invitations.read`/`invitations.write`, a
  `/admin/convites` page to invite an email with roles, resend (new link) and
  revoke, and a public `/convite/<token>` page where the invitee picks a name
  and password: the user is created with the invited roles and signed in.
  Public routes: `GET /invitations/by-token/:token` and
  `POST /invitations/accept`. Mail goes through a port you implement:
  `sendMail()` in `src/lib/mail.ts` (single app) or the `MAIL_SENDER` provider
  of `apps/api/src/modules/mail` (monorepo); both only log to the console
  until you plug in a provider. The accept link is built from `NEXTAUTH_URL`.

Each run appends a marked block to `schema.prisma` (or writes its own file in a
multi-file schema folder), adds the codes to the catalog in `rbac.ts`, a menu
entry with its `permission` and the pt-BR/en/es messages, then copies the module
files. It is idempotent: a second run changes nothing, and a file that already
exists is kept. `--dry-run` lists what it would create or modify. It never
migrates: run `pnpm db:migrate --name add-audit` and `pnpm db:seed` (the seed
syncs the catalog and grants the new permissions to `admin`).

An app that was not generated from the templates (no `src/rbac.ts`, no `Role`
model) is refused. Adopt the runtime pieces there instead:
`createAuditInterceptor` and `@SkipAudit` (`@telamonjs/data/nest`), `computeDiff`
and `redactPayload` (`@telamonjs/data`), `AuditChangesViewer` and
`PermissionMatrix` (`@telamonjs/ui`).

## Lint admin modules

```bash
telamonjs lint [dir]     # default: src/app/admin when it exists, else .
```

Checks admin modules against the list/dialog/hub conventions. `--json` prints
the report as JSON. Exits 1 on errors. The rules live in
[`rules.ts`](https://github.com/telamonjs/telamonjs/blob/main/packages/cli/src/commands/lint/rules.ts).

## Link a local TelamonJS checkout

```bash
telamonjs link [--ui <path>] [--package <path>]   # @telamonjs/ui from the checkout
telamonjs unlink [--package <path>]               # back to the published range
pnpm install                                      # neither command installs
```

`link` points `@telamonjs/ui` at a checkout's `packages/ui` as an injected `file:`
dependency and adds the required `pnpm.overrides` for each package that `ui` declares
as `workspace:^` (`@telamonjs/logger` and `@telamonjs/data`, each a `link:` to its
folder in the checkout's `packages/`) to the workspace root's `package.json`.
`unlink` removes them and restores the range committed at `HEAD`, else `^` plus the
latest published version, never the checkout's own version. The edited
`package.json` is `apps/web/package.json` when it exists, else `./package.json`;
`--ui` defaults to `$TELAMONJS_UI`, else `../telamonjs/packages/ui` next to the
workspace root. Monorepo apps wrap both in `pnpm telamonjs:link` /
`pnpm telamonjs:unlink`, and their husky hooks unlink before each commit and
relink after it.

## Other commands

| Command | What it does |
| --- | --- |
| `telamonjs db dump [name]` | Dump the database into `database/dumps/` with a timestamp |
| `telamonjs db restore` | Restore a dump, picked interactively |
| `telamonjs analyze` | Check a project's TelamonJS setup (version, Prisma, NextAuth, Docker, scripts) and suggest fixes. `-v`, `--json` |
| `telamonjs stats` | Git repository statistics. `-v`, `--json`, `-p, --path <path>` |

Requires Node ≥ 22. The package manager is detected from the launcher
(`pnpm dlx`, `yarn dlx`) or the lockfile, with npm as the fallback.

(MDX, readable on GitHub).
